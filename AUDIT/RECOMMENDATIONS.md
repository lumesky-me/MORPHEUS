# Prioritized Phase 2 review plan

These are recommendations, not changes automatically implemented by this audit.

1. **Resolve release blockers.** Use a disposable supported Windows host for the exact current source. Build the full application, test independent install/profile/Store identities, notification COM registration, upgrade/uninstall and updater artifact/signature behavior. Provide a MORPHEUS-owned Gateway distribution or explicitly supported connection to this source-built Core; upstream Store/npm provisioning does not establish that integration. Do not publish/sign with upstream identities.
2. **Triage affected dependency graphs.** Review the nine high production advisories and the broader moderate findings. Prove reachability where possible; upgrade owning packages with compatible supported fixes and regression tests. Do not blindly override major versions or treat advisory scanner failure as success. Decide a MORPHEUS release audit policy separately.
3. **Prove preserved workflows on Windows.** Test main chat/streaming, sidebar/session switching, separate Settings, provider/model selection, Codex auth with deliberately provisioned test credentials, custom agents, persistent memory, compaction, voice, browser/files, execution approvals, node permissions and MXC deny/allow behavior. Test on x64 and native ARM64 where claimed. Never use the user's real profiles or live sessions.
4. **Investigate browser execution boundaries.** Verify cancellation propagation, resource disposal and response budgets. Use synthetic files and local endpoints to test file-response export and redirect headers. Address only reproduced/confirmed boundary defects with owner-level regression tests.
5. **Review deployment policy and secret storage.** Explicitly document which Core tools are sandboxed and which can run at gateway privilege. Evaluate QuickJS/OS containment where appropriate. Review ACL failure visibility, backups and DPAPI/Credential Manager portability with migration proof; do not silently change auth semantics.
6. **Make validation portable where intended.** Separate Windows-required tests from portable protocol suites, and fix proxy-fixture isolation. Retain failed/unclassified counts until diagnosed. Do not hide failures with blanket skips, retries or relaxed assertions.
7. **Reduce maintenance debt deliberately.** Use the existing architecture ledger and static candidates. Verify dynamic/public entrypoints before deleting anything. Investigate large owners and possible translation duplication one bounded change at a time; do not quantify all flagged code as waste.
8. **Measure before optimizing.** Run reconnect/large-browser-response memory tests, Core worker idle/burst benchmarks, real UI responsiveness traces and representative database/session workloads. Preserve existing functionality and security boundaries.

Phase 1 integration changes are limited to source organization, provenance, presentation, independent identities, safe source-profile initialization and distribution boundaries. Audit recommendations need user review before implementation. This snapshot is not a claim of complete security, Windows readiness, or successful publication.
