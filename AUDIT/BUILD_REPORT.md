# Build and regression report

## Source, host and reproducibility

Exact source versions and import inventory: `UPSTREAM.md`. Linux x86_64, 4 effective CPUs, about 32 GiB RAM, no Windows GUI/SDK/WSL/Inno/PowerShell. Toolchain: checksum-verified Node 26.12.1, integrity-pinned pnpm 12.15.0, .NET SDK 10.0.400. Both Core frozen installs passed; dependency/lock declarations were preserved. Untouched originals were tested outside the MORPHEUS checkout before downstream modifications.

Run Core commands from `components/core`, Windows commands from `components/windows`, root tests from the repository root. Commands requiring networking/process execution used the configured proxy outside the restrictive command sandbox, without disabling TLS verification. Node network/build initialization: `NODE_USE_ENV_PROXY=1 NODE_OPTIONS=--max-old-space-size=8192 OPENCLAW_TSDOWN_MAX_OLD_SPACE_MB=8192`. Initial build failures demonstrated that the explicit tsdown heap setting is separately required when cgroup detection is unavailable. No assertions or security gates were disabled to obtain a passing result.

Reusable setup: `scripts/bootstrap-cloud.sh` verifies the pinned tool artifacts; `scripts/install-cloud.sh` runs frozen install, build, UI build, typecheck, profile tests and source verification with failure propagation. Its constituent steps were exercised; the complete pipeline is not a claim that all existing upstream quality gates pass. Environment `install_script` and `start_skill` were saved as a draft, not published. Processes do not survive publication/restoration.

GitVersion needs real history. The connected MORPHEUS branch has no commits, so imported Windows builds need `-p:DisableGitVersionTask=true -p:Version=0.1.0` for version generation. Original baseline builds did not need this override. No commit, push, release, Store submission or GitHub fork was created. Imported source is staged for review, including original tracked files that inherited ignore rules would otherwise omit.
